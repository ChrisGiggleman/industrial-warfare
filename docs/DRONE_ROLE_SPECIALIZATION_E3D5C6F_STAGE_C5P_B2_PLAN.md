## Scope and player-facing rules
Automated logistics and construction drones have no individual energy, charging delay or powered flight-path requirement. Ordinary work requires the original destination/site and home hub to be authorized; power loss suspends the assignment rather than cancelling it. Material recovery and safe physical return are not ordinary powered work. B2 is isolated to existing specialized single-job prototype and B1 automated mode, separately opt-in and latched before configuration. Legacy and B1-only modes remain unchanged. General completed-building supply logistics, multi-job/fleet dispatch, new placement rules, power extension exemptions, emergency grid restoration jobs, repairs, demolition, world settings, player drones and Main integration are deferred.

## Proposed staged implementation (approval required)
B2a authorization service and isolated fixture: immutable mode plus pinned original scope/hub/network/allocator/site/job/demand; expose reasoned snapshot (invalid authority, hub offline, site uncovered, insufficient supply, forecast available, actual allocation ready). Read-only forecast does not advance timers or allocate. Validate exact identities, finite geometry and actual live services before any action; no caller-supplied powered bool. Register preexisting pole early and verify builder reuses it. Test zero mutation, no pre-escrow deadlock, finite capacity, disconnected network, alternate source, own existing grant, stale/foreign/duplicate authority, legacy opt-out.
B2b logistics interruption: gate reserve, launch, each outbound tick, collect, begin delivery, each delivery tick and unload. Before reserve stay idle if unauthorized. Reserved or outbound empty: release unused exact stock claim, retain original nonterminal lease; physically return and rearm same assignment only after dock proof, then reacquire stock using current availability. If no stock available wait without duplicate claim. Loaded or at delivery: retain original cargo/item/site/job/definition and receiver identity; return physically to original berth using dedicated suspended-loaded states. No unloading at hub or unpowered site; no synthetic stock/refund. Park fully before any resume, even if power restores mid-return; resume same cargo from actual berth without second pickup. After actual unload, staging/escrow remain at site and empty return remains allowed; escrow may be sealed as custody bookkeeping without authorizing construction. Do not begin builder handoff until actual allocation and hub gate are ready. Cancellation while empty/loaded/returning/parked must route into existing terminal claim or physical recovery semantics exactly once; blocked storage capacity retains cargo. No ordinary power check on terminal physical recovery; stale/replaced site quarantines custody unless existing terminal proof permits recovery. Keep single owner and no _process driver.
B2c builder authorization: retain C4 parking/resumption and C4B handback, add hub gate at admission, flight, arrival, work, resume. On loss, freeze progress, release active slot, keep original receipt/escrow/job, return empty; no progress or re-admission until joint authorization and physical arrival. Existing finite allocation remains authoritative. If hub offline while site still powered, suppress scheduler readiness without falsely revoking material custody; if necessary isolate coordinator hook, no global scheduler policy change. Normal completion consumes original escrow once and returns. Cancellation during parking or parked continues existing terminal recovery; no charging calls.
Each substage may be separate commit with isolated F6 validation before next; if implementation requires broader Main/legacy contract changes, stop for approval. Test fixture paths/counts provisional until created. No changes to accepted test assertions.
