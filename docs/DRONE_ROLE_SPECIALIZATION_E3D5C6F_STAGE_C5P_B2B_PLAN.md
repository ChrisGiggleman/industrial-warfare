## Proposed staged implementation
B2b-1 empty lifecycle: add separate latched feature flag and named suspension state/proof on controller/worker, physical berth validation, exact supplier release and nonterminal rearm. Gate initial reserve, launch, outbound tick and collect. Before first reserve wait idle without lease/claim; after claim exists keep original lease on outage, release unused stock once, return empty from actual position, park fully before re-reserving. If stock unavailable after restore, wait in parked state with original lease; reserve only exact five ingots when available, then launch through existing path. Gate lower-level pickup/debit path for opt-in mode so direct calls cannot bypass controller authorization. Empty cancellation during return/parking/reacquisition uses exact original job proof and terminal cleanup, no extra material refund. Use explicit bounded owner steps and clear diagnostics.
B2b-2 loaded lifecycle: gate begin delivery, each delivery tick and unload (also lower-level entry points). Add loaded returning/parked states with original cargo/receiver identity; actual distance-limited motion to left berth; never deposit or clear cargo on outage. Restore mid-return waits until dock verified, then resume same cargo from berth without second debit. Repeat outages safe; cancellation while loaded or parked transfers exact cargo to existing capacity-reserved C2 recovery, including blocked destination wait; terminal recovery does not require ordinary power. Stale job/receiver quarantined. No direct assignment of stock or teleport.
B2b-3 staged and handoff boundary: preserve physically unloaded materials at site; escrow sealing/empty return allowed even offline. While docked wait for exact receipt, escrow, actual allocation and hub authorization before c4_transfer_to_builder; no premature capture/owner transfer. Existing builder configure and reconcile ordering retained; if authorization denied builder may be configured but cannot take ownership. Cancellation uses existing C3 custody ticket/recovery; no builder work enforcement changes. Verify B2a-only and legacy defaults and single owner.
Substages are proposed implementation/test checkpoints within B2b, not B2c. Begin with B2b-1 after approval; stop for local isolated verification before subsequent substage. If code requires general scheduler/Main or unrelated changes, stop and seek approval. Exact paths/counts established only after files created.
