## Approved gameplay direction
Automated logistics and construction drones have no individual battery consumption, charging delay or flight-path power checks. Work authorization belongs to destination building/site; hub must be operational and powered for ordinary dispatch/resume (proposed explicit hub gate; distinguish current prototype hub/source from final consumer model). Physical return/parking and custody recovery remain allowed in blackout; no energy resource simulation for automated drones. Player-controlled exploration drone retains future battery limitation outside powered territory. No per-drone network allocation, no aggregate fleet energy budget in this proposal. Keep specialized roles, physical movement, material escrow, inventory conservation, priority and one owner.

## Proposed implementation scope — approval required
B1: isolated immutable opt-in policy for exact specialized scope, default legacy; fresh instances only, reject runtime mode switch, foreign identity, missing services, invalid delta/coordinates. Separate validated berth registration/token and dock readiness from charging without loosening scope/role/receipt checks. Implement mode-aware movement and route feasibility across pickup, delivery, staging recovery, empty return and retirement. Do not replace existing legacy methods with unconditional true or fake battery values. Distance ranking stable and deterministic. Keep legacy fixture paths, Main, project defaults and existing test files unchanged.
B2: add read-only site authorization policy and nonmutating pre-delivery probe (coverage plus actual available supply, not escrow-dependent allocated flag); recheck before pickup, delivery/unload and work. Existing finite allocator remains authority for construction progress; no allocation without escrow. If power disappears before delivery, do not unload into ordinary unpowered target; suspend original assignment, physically return to exact hub, release unused claims; loaded cargo stays owned by original job/drone in safe berth pending resumption (proposed first implementation), no free deposit or duplicate reserve. If alternative storage recovery is needed on cancel, existing physical capacity-reserved recovery only. Delivered escrow remains intact. Builders freeze progress, release active slot, return empty; restore original job/receipt and re-admit only after authorization and valid dock/worker conditions. Finish parking before resume to avoid competing motion. Repeated outage, cancel while parked, blocked return and stale job must be deterministic; terminal recovery independent of ordinary work power gate, but honor destination admission/capacity. Hub outage blocks new work, not safe return to live physical berth. Destroyed hub/no valid destination is fail-closed diagnostic, not teleport or deletion; generalized reroute deferred.
B3: isolated power-extension placement rule: completed registered valid network anchor within configured mutual link distance, even during generator outage; no authorization from unfinished or disconnected arbitrary towers. Preserve whole footprint coverage for normal builds. Bootstrap initial base/recovery exception explicitly scoped; no infinite placement chain of unfinished towers. Exempt eligible power extensions/generators from site power only, not material/worker/placement requirements; allow restoration work even if hub electrical supply is down using narrowly scoped emergency infrastructure job authorization (proposed to avoid deadlock; no ordinary dispatch). Exact anchor/root validation, generator placement policy and distances require implementation review; do not hardcode illustrative meters. If existing placement/allocator contracts require broader changes, stop for approval before touching Main. Other passive building exemptions remain a proposed data-driven policy, not part of this initial implementation.
C: add isolated suites for policy/guards and dock/movement, logistics blackout and material conservation, builder blackout/cancel, extension geometry/bootstrap. Proposed checks: default legacy/Main opt-out, foreign/stale tokens, duplicate owners, no battery/charger calls or per-drone allocation, valid pre-escrow authorization/no circular wait, uncovered/insufficient supply refusal, outage before pickup/loaded/at unload/staged, same job resume, repeated outage, hub outage, capacity blocked, cancel each phase, physical return and recovery, exactly one completed building, no loss/duplication, invalid routes, extension boundary/unfinished anchor/offline restoration/bootstrap. Counts provisional; create F6 navigator only after real files exist. Run isolated suites, targeted compatibility, then full fresh 73-suite legacy manifest plus new suites on consistent revision; record developer-local results and new counts separately. No old test modifications without separate approval. C5B wrapper revised after C5P acceptance: replace battery telemetry with destination/hub authorization, pause reason, role/berth/cargo/escrow/progress and owner; power toggle tests both logistics and builder, remove charging-dependent manual checks. No Main integration or merge until separate review and acceptance.

## Future roadmap (approved direction, not current implementation)
Construction drones also repair damaged surviving buildings; no separate maintenance drone. Free time-limited automatic repairs by default, configurable material cost and automatic repair option; logistics supplies materials when enabled. Power infrastructure repair exception; repair priority and research upgrades later; destroyed buildings rebuilt rather than repaired. Demolition of completed buildings: per-world 0–100% refund slider, recommended custom default 100%, return original construction materials proportionally (integer rounding policy to finalize); recover stored inventory separately, unfinished cancellation returns unconsumed materials, enemy destruction no construction refund by default. Preserve existing destruction/salvage behavior until separately audited; no double refunds. Per-world customizable difficulty presets (illustrative values not finalized), player drone exploration batteries and research, additional generation/resource types deferred. No repair, demolition, save/world settings, player-drone, combat or resource implementation in C5P.
